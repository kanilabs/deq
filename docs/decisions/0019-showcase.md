# 19. Showcase

- Status: accepted
- Date: 2026-11-19

## Context

Phase 10b adds a showcase of projects that use Deq: zimankit, Zimanyar, Roj, Tajdîn and tsroj, all hosted at `kanilabs.github.io`. Each card needs a live preview, a screenshot fallback, a description in en, ckb and kmr, the Deq shapes the project uses, and links. Visitors can suggest their own projects. Like the videos (ADR 0018), nothing from another site may load until the visitor asks for it.

## Decision

- **Data.** Projects live in `content/showcase.json`, each with an id, name, site URL, repository, shape ids and descriptions in three languages. Descriptions follow each project's own site and repository text. The owner approved the shape ids after comparing each logo with `spec/shapes`. `apps/site/src/lib/showcase.ts` reads the file. `test/showcase.test.ts` checks unique ids, plain https URLs, known shape ids, the three descriptions, and a screenshot at every width.
- **Screenshots.** `e2e/shots.ts` (`pnpm --filter @0xdolan/deq-site shots [id …]`) opens each site at 1280 × 800 in Playwright's Chromium with light colours and reduced motion. Chromium itself encodes the 640 and 1280 px WebP files through a canvas, so no image library is added. The script writes them to `apps/site/public/showcase/`. They are committed, because a build must not depend on other sites being up, and they are regenerated by hand when a project changes.
- **Click to load.** A card shows its screenshot and a "Load live preview" button. On click, a script creates the iframe with DOM calls, with `loading="lazy"`, `referrerpolicy="no-referrer"` and the sandbox `allow-scripts allow-forms allow-popups allow-popups-to-escape-sandbox`. The preview runs over the screenshot. If the frame fires no `load` event within 15 seconds, the frame is removed and a notice offers the "Open site" link, while the screenshot stays.
- **No `allow-same-origin`.** The projects share this site's origin (`kanilabs.github.io`). `allow-same-origin` would give a project this site's DOM, storage and "My shapes" database, so it is never granted, and previews run in an opaque origin. A project that needs storage may not work fully in the preview, and "Open site" remains the full experience. The CSP's `frame-src` already lists `https://kanilabs.github.io` (ADR 0012).
- **Submissions.** `.github/ISSUE_TEMPLATE/showcase.yml` asks for the name, URL, source, description and shape ids. The submitter must also confirm two things: that they run the project or its owner agrees, and that it may be framed and screenshotted.
- **Shapes on the card.** The shapes use the site's `IconGrid`, linking to each icon page.

## Consequences

- To add a project, add an entry to `content/showcase.json` with descriptions in three languages, then run `shots <id>` and commit the two WebP files. The unit test fails until both exist.
- Screenshots go stale as projects change. They are refreshed by hand.
- The ckb and kmr descriptions are AI drafts awaiting native review.
- While building the cards, a light-theme bug from Phase 7 was fixed: `--deq-icon` used Starlight's `--sl-color-black`, which is white in the light theme, so icon tiles drew nearly white glyphs.
